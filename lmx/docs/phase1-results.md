# Phase 1 結果（2026-11-04）: 読み取り専用ライブラリ

## できたこと

- **lmx-core**: 設定（`data/lmx.toml`、LoRA Manager の `settings.json` からルートを読み込み可）、壊れたサイドカーに強い読み込み、差分スキャン（size/mtime 比較・並列パース）、SQLite インデックス、メモリ上の検索・絞り込み・並べ替え・ページング・ファセット。
- **lmx-server**: `/api/status` `/api/scan` `/api/models` `/api/models/{id}` `/api/folders` `/api/facets` `/api/preview/{id}`。起動時は保存済みインデックスから即座に応答し、裏で差分スキャン。大きい静止画プレビューは JPEG サムネイル（長辺 512px）をキャッシュ。
- **PWA**: 種類タブ（LoRA / Checkpoint / Embedding / その他）、検索、絞り込みシート（並べ替え・お気に入り・要修復・ベースモデル・フォルダ）、仮想スクロールのカード一覧、詳細シート（LoRA タグ・トリガーワードのコピー、Civitai で開く、サンプル画像、ファイル情報）、設定（テーマ・R 以上のぼかし・動画プレビュー・再スキャン・状態表示）。Android の戻るボタンでシートが閉じる。
- **起動スクリプト**: `scripts/start-lmx.ps1`（隠しウィンドウで常駐、ログ追記、PID 記録）/ `scripts/stop-lmx.ps1`（記録した PID だけ停止）。

## テスト

- Rust 33 件（core 25 / server 単体 3 / HTTP 結合 3 / scan クレート 2）すべて成功。
  - スキャンが**どのファイルも変更しない**ことを、テスト用フォルダ全ファイルの SHA256 を前後比較して確認するテストを含む。
  - 実ライブラリで見つかった破損の形（末尾の余分な `}`、文字列中の生の制御文字）を再現したテストを含む。
- Web 12 件（グリッド計算、表示行の範囲、クエリ文字列、HTML→テキスト変換で `<script>` や `onerror` が残らないこと など）成功。`vue-tsc` 型チェック込みでビルド成功。

## 本番データを変更していないことの確認

- 起動前後で `.metadata.json` 15,743 件の (size, mtime) を記録して比較 → 238 件が変化。
- 変化した 238 件は**すべて**、同時に動いていた本家 LoRA Manager のログ（`Fetched metadata for … via CivitAI API`）に名前が出ている。lmx 起因の変更は 0 件。
- lmx のコードでファイルを書くのは、テストと `data/thumbs/`（lmx 自身のキャッシュ）だけ。

## 破損サイドカーの表示

- 制御文字の 1 件は、文字列中の制御文字を補正する救出処理でも読めなかった（文字列の外にも壊れがあると推測、未調査）。
