# Phase 4 結果: 仕上げ（2026-11-04）

ブランチ `feature/lmx-phase4`。

## できたこと

| 機能 | 内容 |
|---|---|
| 新しいバージョンの確認 | Civitai の `/models?ids=` で 100 件ずつまとめて取得し、バージョンの id・名前・ベースモデル・公開日・先行公開/要 Buzz だけを `data/updates.json` に保存。判定は本家と同じ「同じベースモデルで、手元の一番新しいコピーより新しく、手元に無く、無視していない」。1 日 1 回の自動確認（既定 ON）、手動確認・中止、モデル単位/バージョン単位の「通知しない」 |
| 表示 | ライブラリのカードに NEW、絞り込み「新バージョンあり」と件数チップ、下のタブにバッジ、詳細シートに新バージョンの一覧と「ダウンロード画面を開く」、設定に一覧（無料のみの絞り込み） |
| 統計 | 件数・容量を種類・ベースモデル・最上位フォルダ・作者別に。Civitai 情報やプレビューの割合、7/30 日以内の追加、重複、大きいファイル |
| パスワード（任意・既定 OFF） | PBKDF2-HMAC-SHA256（12 万回）のハッシュと乱数の秘密鍵を `data/auth.json` に保存。ログインで HttpOnly の Cookie（180 日、HMAC 署名）。`/api/*` はヘルスチェックとログイン以外すべて保護（プレビュー画像も）。画面の外枠は保護しないのでログイン画面が出せる。10 回失敗で 10 分止める。変更すると全端末のログインが切れる。忘れたら `auth.json` を消す |
| 設定のバックアップ | 検索のベースモデル、自動確認の設定、通知しない一覧を JSON 1 つで保存・読み込み。`lmx.toml` は参考として入れ、`key`/`password`/`token`/`secret` を含む行はコメント行も伏せ字 |
| 文書 | `docs/usage.md`（起動・スマホ・設定・data の中身・本家との併用、切り替えと戻し方）、README と `lmx.example.toml` の全項目 |

## 実測（本番ライブラリ）

| 項目 | 結果 |
|---|---|
| 新バージョン確認 | 13,988 モデルを 140 リクエスト・48 秒、失敗 0。結果ファイル 3.9 MB |
| 結果 | 新バージョンのあるモデル 650 件（いま無料で落とせる 647 件）。内訳: LoRA 571、Checkpoint 72、Embedding 7 |
| 正しさ | 無作為に選んだ 5 件を Civitai の単体 API と突き合わせて 5/5 一致（新バージョンが 5 つあるものも含む） |
| Civitai から消えたモデル | 2,350 件。無作為 15 件を単体で引くと 15/15 が 404（本当に削除済み） |
| 速さ | 新バージョン一覧 37 ms、ライブラリの絞り込み 15 ms、統計 39〜48 ms、画面の読み込み 14 ms |
| 常駐メモリ | 起動直後 83 MB、確認の直後 102 MB |

## 判断したこと

- 古いコピーには NEW を付けない: v1 と v2 を持っていて v3 が出たとき、NEW は v2 にだけ付ける（ベースモデルごと）。最初は両方に付けていて「650 モデルなのにファイルは 916 件」とずれたため直した。
- Buzz の価格は出さない: 本家はモデルのページに埋め込まれたデータから価格を読むが、このマシンからは Cloudflare の確認で全部 403（civitai.com・.green・.red、成人向けでないモデルでも）。
- 本家の更新 DB（`cache/model_update/default.sqlite`）は 5 件しか入っていなかったので取り込まない。

## 残り

- 画面の目視確認（利用者）
- 常駐メモリが確認の直後に 100 MB を少し超える。新バージョンの結果を持つ分なので、必要なら持ち方を軽くする
- 本番での `archive_only` 一括実行（本家の一括取得が終わってから、利用者の確認を取る）
