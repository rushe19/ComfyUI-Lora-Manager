# Phase 3 結果: メタデータ管理と書き込み操作（2026-11-04）

ブランチ `feature/lmx-phase3`。

## できたこと

| 機能 | 内容 |
|---|---|
| メタデータ一括取得 | `archive_first`（既定）/ `archive_only` / `civitai_first`。ジョブごとにモードを選べる。進み具合・内訳（ローカル DB / Civitai / 見つからず / スキップ / API 呼び出し数）を表示、中止可 |
| ローカル archive DB | 読み取り専用で開き、lmx 側に sha256 索引（`data/archive_hash.sqlite`）を作る。DB ファイルが変わったら作り直す |
| サイドカー書き込み | 本家と同じ形式（2 スペース・UTF-8・Windows は CRLF・Python と同じ小数表記）。一時ファイル → リネーム。変更前の内容は `data/backups/<時刻>-<操作>/` へ |
| 編集 | 表示名・ベースモデル・タグ・トリガーワード・強さ・メモ・お気に入り・除外。未知のキーと順序は保持 |
| 移動・改名 | プレビューやメタデータなど同名の付属ファイルも一緒に。上書きになる場合は何も動かさずに中止、途中で失敗したら元に戻す |
| 削除 | Windows のゴミ箱へ（付属ファイルごと）。トーストと設定画面の履歴から元に戻せる |
| 一括操作 | 長押しで選択 → お気に入り / タグ追加・削除 / ベース変更 / 移動 / メタデータ取得 / 削除 |
| 重複 | 同じ sha256 のファイルを組で表示、削れる容量も表示 |
| フォルダ監視 | 外部での追加・削除を検知して自動で再スキャン（2 秒静かになってから、5 秒に 1 回まで） |

## 実測

| 項目 | 結果 |
|---|---|
| サイドカーの往復 | 実ファイル 15,611 件すべてが「読む → 書く」でバイト単位で同一（壊れた 24 件と読めない 1 件は対象外） |
| archive 索引 | 705,041 件、初回作成 14.5 s、2 回目以降 0.04 s で開く。15.7k 件の照合 0.16〜0.27 s |
| 当たり見込み | Civitai 情報の無い手元のモデル 7,804 件のうち 4,193 件が archive にある |
| 本家との突き合わせ | 実サイドカーのコピー 70 件（archive にある 60 + 無い 10）を `archive_only` で処理: 0.26 s、Civitai 呼び出し 0。結果を本家 LoRA Manager 自身のマージ処理と比較して 59/59 件一致、本家で 59/59 件読み込める |

## 本家との意図的な違い

- archive から作るとき、本家はライセンス欄を既定値（`allowCommercialUse: ["Sell"]` など）で埋めるが、lmx は archive にある実際の値を入れる。
