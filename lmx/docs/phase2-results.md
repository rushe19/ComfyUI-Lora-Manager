# Phase 2 結果: Civitai 検索とダウンロード（2026-11-04）

ブランチ `feature/lmx-phase2`。テスト: Rust 52 件 + Web 17 件すべて合格。

## できたこと

| 機能 | 内容 |
|---|---|
| Civitai 検索 | キーワード・種類（LoRA/Checkpoint/Embedding/その他）・base model・並び（評価/DL 数/新着）・期間・NSFW。カーソル無限スクロール。結果はタブを移っても保持 |
| Civitai のお気に入り | API キーのユーザーのお気に入りを一覧（`favorites=true`） |
| 所持済み判定 | カードに「所持 n/m」、詳細でバージョン・ファイル単位に「所持」。sha256 → バージョン ID の順で照合。DL 待ちも表示 |
| ダウンロード | ファイル選択（fp16 等）→ 保存先ピッカー（ルート / 既存フォルダ / 新規フォルダ、base model 名に合うフォルダを「おすすめ」表示、種類ごとに前回の保存先を記憶） |
| URL 貼り付け | 複数行一括（最大 50 行）。`/models/{id}`・`?modelVersionId=`・`/model-versions/{id}`・`/api/download/models/{id}` に対応。行ごとに成否表示 |
| キュー | 同時 2 本（`download_concurrency`）、SQLite 永続化、再起動で再開、中止・再試行・履歴の削除、下部ナビにバッジ |
| 完了処理 | `.lmx-part` に書き込み → SHA256 検証 → リネーム → プレビュー保存（`.preview.jpeg` 等）→ 本家互換の `.metadata.json` 生成 → 自動再スキャンで一覧に即反映 |

## 実測（実際の Civitai 通信、サンドボックスのルートに保存）

| 項目 | 結果 |
|---|---|
| 検索 `frieren` 40 件 | 0.49 s（同じ検索の 2 回目はキャッシュで 15 ms）、2 ページ目 0.30 s・重複 0 |
| お気に入り | 3 件 0.24 s |
| 55 MB LoRA | 6.1 s で完了、ハッシュ一致、プレビュー・サイドカー生成、ライブラリ件数 0 → 1 |
| 1.74 GB LoRA の再開 | 103 MB の時点でサーバーを強制終了 → 再起動で `resume at 103358693 bytes -> HTTP 206` → 37 s で完了、ハッシュ一致 |
| 二重投入 | 同じバージョン・ファイルは 409（待ち中）、所持済みは 409「既にライブラリにあります」 |
| UI（ブラウザで操作） | 検索 → 詳細 → 保存先 → DL → DL タブに進捗（MB/s 表示）→ 完了後ライブラリが自動更新。Android の戻る操作で保存先パネル → 詳細の順に閉じる |
| 本番サーバー常駐メモリ | 64 MB（Phase 1: 48 MB） |
| 所持判定の確認 | 手元の Frieren 系 10 件をそれぞれの名前で検索 → 10 件すべて「所持」表示 |

## 安全策

- 保存先は設定済みルートの内側だけ（`..`・ドライブ指定・ルート外は 400）。ファイル名は Windows 予約文字を置換。
- 既存ファイルは上書きしない（同名があれば失敗にして残す）。既存のサイドカー・プレビューも上書きしない。
- ハッシュ不一致は一時ファイルを消して失敗表示。
- API キーはサーバー内だけ。ジョブ一覧の応答からダウンロード URL とメタデータは除外。
- テストは Civitai に通信しない（Range 対応のローカルサーバーと記録済み応答を使用、`civitai_api_base` で差し替え）。

## サイドカーの互換性

- キー順は本家と同じ（`file_name, model_name, …, usage_tips`）。`metadata_source: "civitai_api"`、`from_civitai: true`。
- `civitai` には `/model-versions/{id}` の応答を使う（本家と同じ形。例画像の生成パラメータ `meta` と `creator` を含む）。取れなかったときは `/models/{id}` の該当バージョンで代用。
- `civitai.model` のキーは本家の実ファイルと同じ集合（allowCommercialUse… description, name, nsfw, poi, tags, type）。
- 本家で開いて読めるかの相互運用テストは Phase 3 の完了条件で実施する。

## 計画からの変更

- **進捗は SSE ではなくポーリング**（進行中 1 秒、待機時 5〜15 秒）。スマホがバックグラウンドから戻ったとき再接続処理が要らず、応答も 1 KB 未満なので十分軽い。必要になれば SSE を足す。
- **パステンプレートの代わりに「おすすめフォルダ」＋前回の保存先記憶**。手元のフォルダが base model 名（Anima / Krea2 / Qwen …）で分かれているため、テンプレート文法より実用的と判断。

## 利用者に確認してほしいこと

- スマホ（インストール済み PWA）から検索 → DL → ライブラリに出るまで。本番の保存先は `設定した LoRA ルート` 配下になる。
